# Архитектура и границы версии 0.1

Статус: черновик. Владелец: владелец базы. Создано: 2026-09-17. Проверено для шаблона: 2026-10-14.
Область: платформа знаний базы знаний. Связанные материалы: README.md и MCP-CONTRACT.md. Источники: пользовательский бриф в этой задаче, AGENTS.md проекта, документации из README.

## Модель

- `pages` — текущая рабочая версия. Родитель может быть как статьёй, так и разделом.
- `revisions` — неизменяемые снимки содержимого и метаданных; уникальная пара page_id + number. Системное время хранится в UTC.
- `publications` — отдельный указатель на снимок, индексируемость, постоянный публичный UUID. Смена черновика не сдвигает указатель.
- `operations` — actor + request_id + fingerprint + result. Повтор запроса возвращает прежний результат, другое содержимое под тем же id запрещено.
- `workspace_locks` — короткая транзакционная блокировка изменений структуры и записей. Не допускает конкурентного создания циклов и дублирующей первой операции. Текущая версия обслуживает одну базу; при многопользовательских независимых пространствах блокировка станет per workspace.
- `page_user` — дополнительные разрешения на чтение; API настройки групп / ACL пока нет. В UI доступны «Команда» и «Автор и админ» с наследованием ограничений предков.
- `chunks` — текст смысловых блоков, id блока, revision, модель и вектор. PostgreSQL содержит GIN + pgvector; SQLite — переносимый путь для небольшой локальной базы.
- `widget_definitions` — неизменяемые схемы. Содержимое конкретного блока в этой версии хранится в документе, входит в его снимок.
- `call_recordings` — обработка звонка, зашифрованный URL, закрытое аудио, текст и таймкоды. Очередь `calls` изолирована от общей индексации. Завершение создаёт редакцию статьи со снимком результата; публичные и исторические версии не подтягивают будущие изменения.
- `assets` — закрытые файлы, страница-владелец и конкретный storage disk.
- `settings` — зашифрованные настройки провайдера. Не входят в знания и MCP.
- `password_entries` + `password_entry_user` — отдельное зашифрованное хранилище доступов и адресные права. В статье хранится только UUID ссылки на запись; секреты не попадают в версии, индексы, публичный HTML, OpenRouter или MCP.
- `audits` — охват, проверенные цитаты, варианты правок, выбранные исправления.

## Сохранение

Интерфейс сразу отображает изменения. Через короткую задержку отправляет документ с expected_revision; запросы одного редактора выполняются последовательно. Новые правки во время запроса остаются в буфере и отправляются следующим запросом. При конфликте сервер ничего не перезаписывает, интерфейс предлагает выгрузить локальную копию и загрузить актуальную серверную версию. CRDT и совместные курсоры пока не реализованы.

## Поиск и ИИ

Оба поисковых пути ограничивают выборку правами пользователя до выдачи и передачи контекста. RRF объединяет текстовый и семантический рейтинги. Индексация асинхронна; текстовый поиск доступен сразу после записи. При сбое OpenRouter поиск возвращается к текстовому режиму с уведомлением. Для большого объёма требуется измерение latency / recall на реальных русских запросах.

Аудит читает до 60 релевантных фрагментов и сообщает checked / total. Это ограниченная проверка, а не доказательство непротиворечивости всей базы. Цитаты сверяются с переданными текстами. Предложения модели не исполняются как команды: сервер допускает только замены текстовых блоков с известными id. Правки применяются транзакцией после выбора пользователя. Изменившийся после аудита документ вызывает конфликт и откат всей операции.

## Расширение виджетов

В интерфейсе можно создать именованную схему из текстовых, числовых и логических полей. Сервер проверяет ключи и значения, клиент рисует форму. `Documents::text` даёт текст для поиска, `Documents::html` — безопасный публичный HTML, `WidgetView.vue` — отображение и ввод в приложении.

Для нового поведения (например, интерактивная воронка): добавить зарегистрированный вариант view, Vue-компонент, серверную валидацию и публичный renderer. Произвольный JS из содержимого статьи не исполняется. Версию схемы нельзя незаметно менять под существующими документами.

В этой версии нет централизованных записей, связей между коллекциями, rollup и автоподстановки общего факта в несколько статей. Для них следующий слой — `record_types`, `records`, `record_revisions` и блоки ссылок на записи. Исторический снимок должен фиксировать использованную редакцию записи.
