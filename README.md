# База знаний — шаблон для нового проекта

Статус: актуально для локального запуска; серверные шаблоны — на проверке.<br>
Владелец: администратор нового проекта.<br>
Дата создания и последней проверки: 2026-10-14.<br>
Область: самостоятельная база знаний для одной команды.<br>
Связанные материалы: [серверная установка](docs/DEPLOYMENT.md), [архитектура](docs/ARCHITECTURE.md), [MCP](docs/MCP-CONTRACT.md).<br>
Источник: исходный код marketingbro-kb, снимок от 2026-10-14. Инструкции составлены по коду и конфигурации этого репозитория.

Приложение на Laravel 13, Vue 3, Inertia 3, TypeScript и Tiptap. Подходит для развёртывания похожей базы знаний на другом проекте. Каждый экземпляр имеет собственные БД, файлы, пользователей, ключ шифрования и подключения.

В комплекте: страницы и разделы, редактор с таблицами и медиа, поиск, история редакций, публичные публикации, роли, виджеты, закрытые записи звонков и планёрок, расшифровка и оценка звонков, зашифрованное хранилище доступов, MCP и импорт материалов. Внешние интеграции подключаются отдельно; обычная работа с базой не требует API-ключей.

## Что отсутствует

В Git нет содержимого действующей базы, пользователей, паролей, API-ключей, записей звонков, вложений, экспортов, дампов БД, журналов, `.env` и истории исходного проекта. Production-конфиги используют пример `kb.example.com`. Автоматический импорт регламента из соседней папки удалён. Условия и цены исходного проекта из примера рубрики удалены.

`database/factories` и `tests` содержат только искусственные тестовые значения. Они не являются действующими доступами и не создаются при обычной установке. `db:seed` не создаёт пользователей. Встроенный раздел «Пароли» сохраняет функциональность, но на новой установке пуст.

## Требования

- PHP 8.3+; проверка выполняется на PHP 8.4. Нужны стандартные расширения Laravel, включая PDO, SQLite (`pdo_sqlite`), mbstring, XML/DOM, cURL, fileinfo, OpenSSL и ZIP. Для PostgreSQL добавьте `pdo_pgsql`.
- Composer 2, Node.js 22.12+ и npm.
- SQLite для простого запуска. Для сервера предусмотрены PostgreSQL 16 с pgvector, nginx и PHP-FPM.
- Для PDF-экспорта через офисный конвертер нужен LibreOffice (`soffice`). Для основной работы он необязателен.

Версии зависимостей зафиксированы в `composer.lock` и `package-lock.json`. Устанавливайте их через `install` / `ci`.

## Быстрый локальный запуск

```sh
git clone https://github.com/sxquer/knowledge-base-template.git
cd knowledge-base-template
cp .env.example .env
composer install
npm ci
touch database/database.sqlite
php artisan key:generate --no-interaction
php artisan migrate --no-interaction
npm run build
php artisan serve --host=127.0.0.1 --port=8037
```

Откройте [страницу входа](http://127.0.0.1:8037/login). При пустой БД и `APP_ENV=local` появится форма создания владельца. Задайте свои имя, email и пароль длиной от 12 символов. Создадутся только 10 пустых тематических разделов и 3 схемы виджетов — без статей и подключённых сервисов. Настройте структуру под новый проект через интерфейс.

Если вы сразу используете `APP_ENV=production`, веб-форма создания владельца отключена. Создайте администратора в терминале:

```sh
php artisan kb:admin owner@example.com --name="Владелец базы"
php artisan kb:initialize --no-interaction
```

Вместо `owner@example.com` укажите свою почту. `kb:admin` запросит ваш пароль скрытым вводом. Не передавайте пароль в командной строке. `kb:initialize` можно повторять: существующие разделы и схемы не дублируются.

Для следующего запуска достаточно `php artisan serve --host=127.0.0.1 --port=8037`. Для разработки с автоматической пересборкой запустите `composer run dev`. Очереди запускаются отдельно.

`composer run setup` — сокращённая установка зависимостей, ключа и миграций только для нового экземпляра. Не повторяйте её на действующей базе: этот сценарий заново генерирует `APP_KEY`. Для обновления используйте порядок из серверной инструкции.

## Настройка под другой проект

1. В `.env` задайте `APP_NAME`, `APP_URL` и окружение. Название в готовом интерфейсе — «База знаний»; подписи бренда можно изменить в `resources/js/Pages/Login.vue`, `Workspace.vue`, `resources/js/app.ts` и `resources/views/public.blade.php`. Цвета находятся в `resources/css/app.css`; после изменений выполните `npm run build`.
2. Создайте свою команду и назначьте роли в настройках. Настройки и ключи действующей базы не переносятся.
3. Создайте статьи, разделы и собственные виджеты. По умолчанию установщик добавляет маркетинговую структуру; её можно переименовать или изменить в `app/Console/Commands/InitializeKnowledge.php` до первой инициализации.
4. Для другого сервера используйте [инструкцию развёртывания](docs/DEPLOYMENT.md). Для нескольких экземпляров выделите каждому свой каталог, домен, пользователя ОС, порт БД и имя Docker Compose-проекта.

## Очереди и подключения

Обычный текстовый поиск работает без внешнего провайдера. Ключ OpenRouter, модели и настройки расшифровки задаются в интерфейсе; сохраняются зашифрованными в БД. Ключи нужны только для соответствующих внешних функций. Индексация отправляет провайдеру текст статей, а расшифровка — аудио; включайте эти функции после настройки нового проекта.

Индексация и аудит:

```sh
php artisan queue:work --sleep=2 --tries=3 --timeout=120
```

Обработка звонков использует отдельное подключение `calls` с очередью в БД, даже если общая очередь переведена на Redis:

```sh
php artisan queue:work calls --queue=calls --sleep=2 --tries=3 --timeout=150
```

Импорт Sipuni по умолчанию выключен. Задайте свой аккаунт, секрет, период и права в настройках звонков. Настройте критерии оценки под свой продукт. `resources/call-evaluation-rubric-v2.json` — искусственная рубрика для автоматических тестов, а не действующий регламент. При включённом импорте выполните `php artisan kb:sync-sipuni`; автоматический запуск на сервере описан отдельно.

`OPENROUTER_PROXY` и `XAI_PROXY` в `.env` необязательны и по умолчанию пусты. Настройки VPN и прокси исходного сервера не включены.

## PostgreSQL и Redis локально

`compose.yaml` запускает только PostgreSQL с pgvector и Redis; приложение работает на хосте. В `.env` замените настройки БД:

```dotenv
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=55432
DB_DATABASE=knowledge_base
DB_USERNAME=knowledge_base
DB_PASSWORD=
```

Заполните `DB_PASSWORD` собственным новым паролем, затем:

```sh
docker compose up -d --wait
php artisan config:clear
php artisan migrate --no-interaction
```

Это новая пустая БД; данные SQLite не переносятся автоматически. При необходимости повторите создание администратора. Миграция PostgreSQL включает `CREATE EXTENSION vector`; пользователь должен иметь это право. Redis необязателен: для его использования установите PHP-расширение `redis`, задайте `QUEUE_CONNECTION=redis`, `CACHE_STORE=redis`, `REDIS_PORT=56379`, затем очистите кеш конфигурации. По умолчанию очередь и кеш используют БД.

## Файлы, резервные копии и импорт

Вложения по умолчанию хранятся в закрытом `storage/app/private` и выдаются через маршрут с проверкой прав. Для S3 настройте свои AWS-переменные и `KB_ASSET_DISK=s3`.

Для восстановления нужны три составляющие: БД, `storage` и исходный `.env` с `APP_KEY`. Ключ шифрует интеграционные настройки, ссылки звонков и записи раздела «Пароли». Сохраняйте его отдельно от Git. `key:generate` выполняйте только при первой установке: смена ключа без процедуры миграции делает существующие зашифрованные записи нечитаемыми.

Импорт своей коллекции выполняется через `php artisan kb:import /absolute/path/manifest.json` либо `php artisan kb:import-drive /absolute/path/manifest.json`. Это импорт подготовленного экспорта, а не автоматическое подключение Google Drive. Посмотрите команды с `--help`; реальные манифесты и вложения храните в исключённой из Git папке `imports` или вне репозитория.

## MCP

Endpoint: `/mcp`, транспорт Streamable HTTP. Администратор создаёт персональный токен в интерфейсе. Клиент использует заголовок `Authorization: Bearer <свой токен>`. Токен действует 90 дней; права пользователя и страницы проверяются отдельно. Полный порядок чтения и записи описан в [MCP-соглашении](docs/MCP-CONTRACT.md).

## Проверка установки

```sh
php artisan test --compact
npm run build
composer lint
npm run format:check
```

Проверьте вход, создание статьи, сохранение после перезагрузки, поиск и загрузку тестового вложения. `/up` должен отвечать HTTP 200; он подтверждает запуск приложения, но не заменяет проверку БД, очередей и файлов. Зависимости внешних сервисов тесты заменяют подставными ответами.

Проверено 2026-10-14 на PHP 8.4 и Node.js 22: 119 тестов, 847 проверок, сборка Vite/TypeScript, Pint и Prettier. Миграции и пустой seeder выполнены на новой SQLite; таблицы пользователей, статей, настроек, доступов, файлов и звонков остались пустыми. Проверены создание production-кешей и синтаксис обоих Docker Compose-конфигов. Развёртывание нового VPS и PostgreSQL-миграции здесь не выполнялись.

## Типичные проблемы

- **SQLite database does not exist:** выполните `touch database/database.sqlite` из корня проекта. Если задан `DB_DATABASE`, проверьте путь.
- **No application encryption key:** на новой установке выполните `php artisan key:generate`. На существующей восстановите её прежний ключ.
- **Vite manifest not found:** выполните `npm ci` и `npm run build`.
- **Permission denied / ошибка 500:** пользователь PHP должен иметь запись в `storage` и `bootstrap/cache`. Подробности ошибки находятся в локальном `storage/logs/laravel.log`.
- **Не создаётся первый владелец:** форма доступна только при `APP_ENV=local` и отсутствии пользователей. В production используйте `kb:admin`.
- **Расшифровка или индексация ожидают:** проверьте соответствующий ключ и отдельный worker, затем `php artisan queue:failed`.
- **Ошибка `soffice`:** установите LibreOffice либо задайте путь в `KB_EXPORT_SOFFICE_BINARY`.
